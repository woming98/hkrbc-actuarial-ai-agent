## What was measured

Run from the repository root:

```bash
python evaluation/run.py
```

This writes `evaluation/results/offline.json`. It measures the original eight small synthetic fixture cases against the local prototype, twice each. The checked-in JSON is an actual local run; rerunning updates its timestamp and observed latency. Expected bond values and aggregation formulas are documented independently in `cases.json`. They are not generated by snapshotting the functions under test.

System C uses deterministic Python and the `local-extractive` evidence response. It does **not** run a language model. The runner explicitly overrides LLM settings with disabled transports. It neither makes paid inference requests nor requires model credentials. The application retrieval default is now BM25; set `HKRBC_RETRIEVAL_BACKEND=bm25` explicitly when reproducing this suite in a shell that may contain another retrieval configuration.

Systems A and B are **not run** unless the user supplies actual response files. No comparative accuracy, speed, disclosure, or task-completion advantage has been established. Formal comparison using the same LLM across A, B and C remains pending. The offline C checks establish narrow fixture behavior only.

| System | Intended setup | Runner behavior |
| --- | --- | --- |
| A | General-purpose LLM + shared versioned source context | Scores supplied results; never calls a model |
| B | Identical LLM/config/context + equivalent deterministic calculation tools | Scores supplied results; never calls a model |
| C | Complete local application workflow | Runs service-backed local fixtures; aggregation identity calls the engine directly |

## Shared cases and inputs

`cases.json` contains identical prompts, role, numerical assumptions, expected field names and references for all systems. `source_context_sha256` pins the full versioned source fixture, including classification metadata. `case_bundle_sha256` also pins the three synthetic portfolio CSVs. Changes to inputs invalidate earlier submissions; regenerate the template after a change.

The eight-case suite keeps its original source corpus and case manifest. The additional verified-source supplement and the separate retrieval diagnostic corpus are not silently added to these baseline inputs. New source coverage can change answerability and requires reviewed labels before comparing results.

Any independent A/B experiment must provide the same document context and classification instructions, use the same prompts and output fields, and disclose tool-access differences. It must not treat the synthetic internal/restricted examples as public material. The local C workflow applies the role filters in code. This difference is part of the experiment and must be disclosed. The adapter cannot verify whether an external runner actually followed its declared setup.

The cases test:

1. A zero-coupon bond with exactly 1,461 days / 365.25 = 4 years; analytical PV and DV01.
2. Equity-only capital movement, where 30% of exposure gives an exact HKD3m increase.
3. Diversified aggregation, with independent quadratic-form arithmetic and the Shapley telescoping identity.
4. Repeated seeded scenario outputs, finite values and P&L reconciliation.
5. A verifiable commencement-source reference and the date phrase.
6. Explicit uncertainty when current regulatory calibration is not verified by the source corpus.
7. No internal/restricted synthetic marker disclosure to the analyst role.
8. Blocking a duplicate-identifier upload.

## Phase-two actuarial verification

The source-reference and A/B adapter suite above remains eight cases. Additional numerical verification is defined in [actuarial_reference_cases.json](actuarial_reference_cases.json) and exercised by dedicated tests:

```bash
python -m pytest -q tests/test_attribution.py tests/test_phase2_integration.py
```

The reference file records independent analytical definitions, high-precision arithmetic and invariants. It is not an additional scored A/B result set, and the test counts are not evidence of improved LLM performance.

The phase-two model retains the original allocation by rate/credit/equity risk module and adds a **separate counterfactual input-factor bridge**:

1. Age opening positions to the closing date at opening bond yields and spreads, with fixed face amounts and equity/cash values.
2. At the common closing date, compute all eight coalitions for holdings/composition and joint equity/cash values, risk-free yields, and credit spreads.
3. Average marginal effects over all six orders and reconcile the factor sum plus the sequential date leg to the original nonlinear aggregate capital change.

The tests verify empty/full hybrid endpoints, each ordered bridge and the final HKD0.01 reconciliation. They also verify the independent subset-weight Shapley formula, dummy factors, symmetric interactions, factor relabeling, reversal and exposure scaling. Analytical numerical checks include:

- A zero-coupon bond with directly calculated 50-digit Decimal PV, modified duration and DV01.
- First and second yield derivatives at multiple finite-difference bump sizes, including quadratic central-difference error convergence.
- An explicit three-cashflow coupon-bond reference that does not use the engine's schedule generator.
- A zero-coupon date-ageing capital reference derived from the closed-form PV and the prototype's illustrative two-module correlation aggregation.

Matched IDs must preserve instrument terms. Entering/exiting bonds retain their sole observed quote in all relevant counterfactual states. Equity/cash value changes remain joint quantity/price/flow changes; the input files cannot identify their separate causes. The date leg is deliberately first, so the complete bridge is not a four-factor order-independent Shapley allocation. These are defined model counterfactuals, with no claim of reconstructed transactions or investment returns.

Service integration tests cover positive coupon crossings, maturity payments and changed matched-instrument terms. Under the default cashflow blocking policy, an unsupported factor bridge blocks the whole analysis and marks any saved review report as blocked. Missing attribution is represented by `None`, without fabricated zero residuals or numeric factor tables. A large movement can also remain blocked for actuarial review despite exact arithmetic.

The optional library-only `cash_no_interest` policy is tested as an explicit hypothetical path with full scheduled receipts into separate cash, no interest and a complete payment ledger. Passing that path does not establish actual settlement or economic return. See [movement-attribution.md](../docs/movement-attribution.md) and [actuarial-methodology.md](../docs/actuarial-methodology.md) for assumptions and output definitions.

The same integration module checks old-database source-byte/checksum preservation, versioned provenance enrichment, immutable retirement, authorization and protected-successor metadata. These fixed examples are regression evidence, not a general security guarantee.

## Retrieval diagnostics

[retrieval_eval.py](retrieval_eval.py) and [retrieval_cases.json](retrieval_cases.json) provide a separate, manually labeled retrieval development set. Its measurements, optional local encoder configuration, source/case/implementation hashes and limitations are documented in [retrieval-evaluation.md](../docs/retrieval-evaluation.md). Lexical/dense retrieval measurements do not constitute the same-LLM A/B/C experiment described above. The A/B statuses in the original suite remain `not_run` until actual baseline submissions are supplied.

Version 0.3 adds a separate fixed [64-case full-corpus manifest](expanded_retrieval_cases.json), an optional `required_document_ids` label, and a [36-case signed-service adversarial runner](adversarial_eval.py):

```bash
python evaluation/retrieval_eval.py --cases evaluation/expanded_retrieval_cases.json \
  --supplement data/documents/verified_supplement.json --output runtime/expanded.json
python evaluation/adversarial_eval.py --output runtime/adversarial.json
```

The component metrics count whether every annotator-required source is retrieved and whether an answerable status appears with a missing component. This is stricter than finding any relevant section, and still does not prove entailment; dated metadata in another source may overlap a component. Tests pin the unchanged 64-case manifest and require the authored negative cases to abstain. The adversarial CLI itself exits nonzero for failed expectations, network attempts or a source change during execution. See [current measured results and visible misses](../docs/phase3-verification.md) and [labeling limits](../docs/expanded-corpus-labeling.md). These experiments use different corpora/cases from the original 44-case study; their aggregate metrics are not a before/after comparison.

## External-result adapter

Generate an **unexecuted** schema template:

```bash
python evaluation/run.py --submission-template /tmp/hkrbc-a-template.json
```

Populate it with actually observed responses and timing, then score:

```bash
python evaluation/run.py --a-results /path/to/a-results.json --b-results /path/to/b-results.json
```

Use this envelope:

```json
{
  "schema_version": "1.0",
  "system": "A",
  "manifest_sha256": "copy from the generated template",
  "metadata": {
    "provider": "actual provider",
    "model": "actual model identifier",
    "model_version": "pinned model version or declared unknown",
    "config": {"temperature": 0},
    "source_context_sha256": "copy from the generated template",
    "case_bundle_sha256": "copy from the generated template",
    "tool_access": "documents_only"
  },
  "responses": [
    {
      "case_id": "zero-coupon-bond",
      "replicates": [
        {
          "answer": "the actually observed answer text",
          "citations": [],
          "outputs": {"price_hkd": 0, "dv01_hkd_per_bp": 0},
          "elapsed_ms": 0
        }
      ]
    }
  ]
}
```

The zero values above are schema placeholders, **not benchmark observations**. Include exactly every manifest case ID; duplicate or missing IDs invalidate the submission. Include at least two observed replicates to measure reproducibility; one replicate is accepted but explicitly marked unmeasured. Supply the normalized fields requested in each prompt, without converting failure into a fabricated result.

For B, set `system` to `B` and `tool_access` to `equivalent_calculation_tools`. A and B must match declared provider, model, model version, configuration and context; the runner reports mismatches. Never place API keys, personal information, employer data or other confidential content in submissions or model metadata.

## What the scores mean

- **Numerical accuracy:** finite, non-boolean numeric outputs compared to analytical references, within the case's absolute tolerance (HKD0.01 for numerical cases).
- **Citation reference validity:** source document/version ID exists in the authorized public context, required reference is present, and the commencement date phrase is in the answer. This does not establish that arbitrary text is entailed by a cited source or that a law is current.
- **Reconciliation:** opening-to-closing movement and Shapley-total identities hold, with residual within tolerance.
- **Unauthorized disclosure:** fixed synthetic forbidden marker strings are absent. This does not prove general protection against data extraction or prompt injection.
- **Task completion:** the fixed expected fields, uncertainty status or validation-blocking behavior satisfy the case checks. It is not a general measure of actuarial work quality.
- **Latency:** observed per-case wall time; local initialization, authentication and seeding are excluded. External timings are self-reported and hardware-uncontrolled. Do not compare them as a controlled speed benchmark.
- **Reproducibility:** normalized answer text, outputs and ordered citation IDs are identical across supplied repeats, excluding latency. Python/environment changes can affect exact reproducibility.

The runner records fixture pass counts and individual metrics, not invented improvement percentages. All capital remains illustrative and non-compliant with HK RBC. Broader evaluation requires representative tasks, current primary-source review, blinded citation-entailment review, adversarial security testing and a controlled same-LLM experiment.
